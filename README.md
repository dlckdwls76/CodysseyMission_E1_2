# Python 기초 퀴즈 게임

Python 기본 문법, 클래스, JSON 파일 입출력, 예외 처리를 연습하기 위해 만든 터미널 퀴즈 게임입니다. 퀴즈 풀기, 퀴즈 추가, 목록 보기, 최고 점수 확인 기능을 제공하며 프로그램을 다시 실행해도 추가한 퀴즈와 최고 점수가 유지됩니다.

## 프로젝트 개요

이 프로젝트의 목표는 동작하는 콘솔 프로그램을 처음부터 끝까지 구현하며 다음 내용을 익히는 것입니다.

- 변수와 `int`, `str`, `bool`, `list`, `dict` 자료형
- `if/elif/else` 조건문과 `for`, `while` 반복문
- 함수의 매개변수와 반환값
- 클래스, 객체, `__init__`, `self`, 속성, 메서드
- `try/except`를 활용한 예외 처리
- UTF-8 JSON 파일 저장 및 불러오기
- Git 커밋, 브랜치, 병합, clone, pull 흐름

## 퀴즈 주제와 선정 이유

기본 퀴즈 5개가 포함되어 있으며 사용자가 직접 새 문제를 추가할 수 있습니다.

## 기능 목록

### 퀴즈 풀기

- 저장된 퀴즈를 차례대로 출제합니다.
- 문제마다 4개의 선택지를 표시합니다.
- 정답 번호를 입력하면 정답 또는 오답 여부를 알려 줍니다.
- 모든 문제를 풀면 정답 수와 100점 기준 점수를 표시합니다.
- 기존 최고 점수보다 높으면 최고 기록을 갱신합니다.

### 퀴즈 추가

- 문제, 선택지 4개, 정답 번호를 입력하여 문제를 추가합니다.
- 빈 입력과 범위를 벗어난 정답 번호를 처리합니다.
- 추가한 문제를 `state.json`에 즉시 저장합니다.

### 퀴즈 목록

- 저장된 퀴즈의 번호와 문제 내용을 확인합니다.
- 퀴즈가 없는 경우 안내 메시지를 표시합니다.

### 점수 확인

- 최고 점수, 정답 수, 전체 문제 수를 확인합니다.
- 아직 게임을 하지 않은 경우 기록이 없음을 알려 줍니다.

### 예외 처리와 안전한 종료

- 입력값 앞뒤 공백 제거
- 빈 입력 처리
- 숫자가 아닌 입력 처리
- 허용 범위를 벗어난 숫자 처리
- 잘못된 입력 후 재입력
- `Ctrl+C`와 `EOFError` 발생 시 저장 후 안전하게 종료
- `state.json`이 없을 때 기본 퀴즈 사용
- `state.json`이 손상되었을 때 기본 데이터로 복구
- 파일 읽기와 쓰기 오류 안내

## 클래스 구조

### 클래스를 사용한 이유

이 프로젝트는 퀴즈 데이터와 게임 진행 상태를 함께 관리하기 위해 클래스를 사용했습니다.

- `Quiz` 클래스는 문제, 선택지, 정답처럼 하나의 퀴즈에 속하는 데이터를 하나의 객체로 묶습니다.
- `QuizGame` 클래스는 퀴즈 목록, 최고 점수, 게임 실행 및 저장 기능을 한곳에서 관리합니다.
- `StateStore` 클래스는 JSON 파일 입출력과 롤링 백업을 게임 진행 코드에서 분리합니다.
- 클래스별로 역할을 분리하여 코드의 구조를 쉽게 이해하고 수정할 수 있습니다.
- 새로운 퀴즈 기능이나 게임 규칙이 추가되더라도 관련 클래스만 확장할 수 있습니다.
- 여러 퀴즈를 각각 독립된 `Quiz` 객체로 생성하여 동일한 구조로 관리할 수 있습니다.

### 함수형 설계와의 차이

함수만 사용하는 방식에서는 퀴즈 목록과 최고 점수 같은 데이터를 여러 함수에 인자로 전달하거나 전역 변수로 관리해야 합니다. 이 경우 프로그램이 커질수록 어떤 함수가 어떤 데이터를 변경하는지 파악하기 어려워질 수 있습니다.

클래스를 사용하면 데이터와 해당 데이터를 처리하는 기능을 하나로 묶을 수 있습니다. 예를 들어 `Quiz` 객체는 문제 데이터를 보관하면서 `display()`와 `check_answer()`를 통해 자신의 출력과 정답 확인을 직접 처리합니다. `QuizGame` 객체도 게임 상태를 보관하면서 `run()`, `play_quiz()`, `save_state()` 등의 기능을 함께 관리합니다.

| 구분 | 함수 중심 설계 | 클래스 중심 설계 |
| --- | --- | --- |
| 데이터 관리 | 인자 또는 전역 변수로 전달 | 객체의 속성으로 관리 |
| 기능 구성 | 개별 함수로 분리 | 관련 데이터를 다루는 메서드로 구성 |
| 상태 유지 | 별도의 변수 관리 필요 | 객체 내부에서 상태 유지 |
| 확장성 | 함수와 인자 수정이 많아질 수 있음 | 관련 클래스 중심으로 확장 가능 |
| 적합한 경우 | 상태가 적고 단순한 프로그램 | 여러 데이터와 상태를 함께 관리하는 프로그램 |

## state.json 설명

데이터는 프로젝트 루트의 `state.json`에 UTF-8로 저장합니다.

### 자동 롤링 백업 전략

프로그램은 `state.json`을 덮어쓰기 전에 기존 파일을 자동으로 백업합니다. 백업은 최신 3개 버전을 보존하며 새로 저장할 때마다 다음과 같이 순환합니다.

| 파일 | 내용 |
| --- | --- |
| `state.json.bak.1` | 가장 최근 저장 직전의 데이터 |
| `state.json.bak.2` | 그 이전 데이터 |
| `state.json.bak.3` | 가장 오래 보존하는 데이터 |

네 번째 백업이 필요한 시점에는 기존 `bak.3`을 제거하고 `bak.2`를 `bak.3`으로, `bak.1`을 `bak.2`로 이동한 뒤 현재 `state.json`을 새 `bak.1`로 복사합니다. 따라서 백업 파일이 계속 쌓이지 않으면서 최근 세 버전으로 되돌릴 수 있습니다. 파일이 손상되어 기본 데이터로 복구되는 경우에도 손상된 원본은 먼저 백업되어 문제 원인을 확인할 수 있으며, 그보다 앞선 백업 버전도 유지됩니다.

백업 파일은 실행 중 생성되는 로컬 데이터이므로 `.gitignore`의 `state.json.bak.*` 규칙으로 Git 커밋에서 제외합니다. 복원이 필요하면 프로그램을 종료한 후 현재 `state.json`을 별도 보관하고, 원하는 백업 파일을 `state.json`이라는 이름으로 복사하여 다시 실행합니다.

### JSON을 선택한 이유

이 프로젝트에서는 퀴즈 목록과 최고 점수를 간단하게 저장하기 위해 JSON 형식을 선택했습니다. JSON은 사람이 직접 읽고 수정하기 쉬우며, 키와 값의 구조를 사용하므로 퀴즈의 문제·선택지·정답 관계를 명확하게 표현할 수 있습니다. 또한 별도의 데이터베이스를 설치할 필요가 없고 텍스트 파일이라 비교적 가벼워서 소규모 콘솔 프로그램에 적합합니다. Python 표준 라이브러리의 `json` 모듈로 바로 처리할 수 있어 외부 라이브러리도 필요하지 않습니다.

| 장점 | 설명 |
| --- | --- |
| 가독성 | 사람이 파일 내용을 쉽게 읽고 데이터 구조를 확인할 수 있습니다. |
| 경량성 | 별도의 데이터베이스 서버 없이 하나의 작은 텍스트 파일로 저장할 수 있습니다. |
| 호환성 | 다양한 운영체제와 프로그래밍 언어에서 널리 지원됩니다. |
| 구조 표현 | 배열과 객체를 이용해 퀴즈 목록과 최고 점수를 자연스럽게 표현할 수 있습니다. |
| 표준 라이브러리 지원 | Python의 `json` 모듈만으로 저장과 불러오기가 가능합니다. |

JSON은 모든 상황에 적합한 것은 아닙니다. 데이터가 많아지면 파일 전체를 읽고 다시 저장해야 하므로 처리 속도와 메모리 사용량이 증가할 수 있고, 여러 사용자가 동시에 수정할 때 충돌이 발생할 수 있습니다. 또한 데이터 검색, 관계 설정, 접근 권한 관리 기능이 부족합니다. 따라서 현재처럼 데이터 규모가 작고 한 사용자가 실행하는 프로그램에는 JSON이 적합하지만, 데이터와 사용자가 많아지면 SQLite 같은 데이터베이스 사용을 고려할 수 있습니다.

### 퀴즈 1,000개 확장 시 분석

현재 프로그램은 실행할 때 JSON 파일의 모든 퀴즈를 읽어 `Quiz` 객체 목록으로 변환하고, 저장할 때도 전체 목록을 다시 JSON으로 기록합니다. 퀴즈가 1,000개로 늘어나도 일반적인 개인용 컴퓨터에서는 실행할 수 있지만, 데이터 수에 비례해 다음 비용과 한계가 커집니다.

| 항목 | 현재 방식의 영향 | 개선 방법 |
| --- | --- | --- |
| 초기 로딩 | 1,000개 항목 전체를 읽고 객체로 변환하므로 로딩 시간이 데이터 수에 비례해 증가합니다. | 필요한 범위만 읽는 데이터베이스 또는 페이지 단위 로딩을 사용합니다. |
| 저장 성능 | 퀴즈 하나나 점수 하나만 바뀌어도 JSON 파일 전체를 다시 기록합니다. | 변경된 행만 갱신할 수 있는 SQLite를 사용합니다. |
| 메모리 | 원본 JSON 데이터와 변환된 `Quiz` 객체가 메모리에 함께 존재할 수 있어 파일 크기보다 더 많은 메모리를 사용합니다. | 필요한 데이터만 메모리에 올리는 지연 로딩 방식을 적용합니다. |
| 검색 성능 | 현재 리스트를 처음부터 순회하므로 번호·문제 검색은 최악의 경우 1,000개를 모두 확인하는 `O(n)` 선형 검색입니다. | 고유 ID를 키로 사용하는 딕셔너리 인덱스나 데이터베이스 인덱스를 사용합니다. |
| 동시 수정 | 여러 실행 프로세스가 같은 파일을 저장하면 변경 내용이 덮어써지거나 파일이 손상될 수 있습니다. | 트랜잭션과 잠금을 지원하는 데이터베이스를 사용합니다. |

메모리 사용량은 문제와 선택지 문자열의 길이, Python 객체의 부가 비용에 따라 달라지므로 JSON 파일 크기만으로 정확히 계산할 수 없습니다. 다만 모든 데이터를 한 번에 객체로 생성하는 현재 구조에서는 퀴즈 수가 증가할수록 메모리 사용량도 대체로 선형으로 증가합니다.

JSON 방식을 유지한다면 각 퀴즈에 고유한 `id`를 부여하고 `{id: Quiz}` 형태의 딕셔너리 인덱스를 만들어 ID 검색을 평균 `O(1)`로 개선할 수 있습니다. 하지만 문제 내용의 부분 검색이나 여러 조건을 조합한 검색에는 별도의 인덱스가 추가로 필요합니다. 데이터가 1,000개 이상으로 계속 증가하거나 검색·수정이 빈번해지면 `id`와 문제 내용에 인덱스를 설정한 SQLite로 전환하는 것이 더 적합합니다.

```json
{
  "quizzes": [
    {
      "question": "Python에서 문자열을 나타내는 자료형은?",
      "choices": ["int", "str", "bool", "list"],
      "answer": 2
    }
  ],
  "best_score": {
    "correct": 4,
    "total": 5,
    "score": 80
  }
}
```

| 필드 | 자료형 | 설명 |
| --- | --- | --- |
| `quizzes` | `list` | 전체 퀴즈 목록 |
| `question` | `str` | 문제 내용 |
| `choices` | `list` | 4개의 선택지 |
| `answer` | `int` | 1~4 범위의 정답 번호 |
| `best_score` | `dict` 또는 `null` | 최고 정답 수, 문제 수, 점수 |

## Git 작업 확인

전체 커밋과 브랜치 병합 기록은 다음 명령으로 확인합니다.

```bash
git log --oneline --graph --all --decorate
```

### 커밋 단위와 메시지 정책

커밋은 한 가지 목적만 담는 작은 단위로 작성합니다. 기능 구현, 오류 수정, 테스트, 문서 변경을 가능한 한 서로 다른 커밋으로 분리하며, 각 커밋은 그 자체로 실행 가능하고 변경 이유를 설명할 수 있어야 합니다. 관련 없는 파일을 한꺼번에 추가하는 `git add .` 대신 `git add <파일 경로>`를 사용해 커밋 범위를 확인합니다.

- 하나의 기능이나 하나의 오류 수정만 한 커밋에 포함합니다.
- 기능 코드와 그 기능을 검증하는 테스트는 함께 커밋할 수 있습니다.
- 기능과 관계없는 문서·데이터·서식 변경은 별도 커밋으로 분리합니다.
- 임시 코드, 디버깅 출력, 의미 없는 빈 커밋은 제출 기록에 포함하지 않습니다.
- 커밋하기 전에 `git diff --staged`로 포함된 변경을 확인합니다.

커밋 메시지는 다음 템플릿을 사용합니다.

```text
<type>(<scope>): <변경 내용을 요약한 명령형 문장>
```

`scope`는 변경 범위를 더 명확하게 표시할 때만 사용하며 생략할 수 있습니다. 제목은 한 줄로 간결하게 작성하고, 무엇을 변경했는지 드러나는 동사로 시작합니다.

| 타입 | 사용 목적 | 예시 |
| --- | --- | --- |
| `feat` | 새로운 기능 추가 | `feat(quiz): 퀴즈 추가 기능 구현` |
| `fix` | 오류 수정 | `fix(storage): 손상된 JSON 복구 오류 수정` |
| `docs` | README 등 문서 변경 | `docs: Git 커밋 정책 추가` |
| `test` | 테스트 추가 또는 수정 | `test(backup): 롤링 백업 테스트 추가` |
| `refactor` | 동작 변화 없는 코드 구조 개선 | `refactor(game): 입력 처리 함수 분리` |
| `chore` | 설정·정리 등 보조 작업 | `chore: 백업 파일을 Git 제외 목록에 추가` |

개발이 끝난 뒤 clone과 pull 실습은 [Git 실습 안내](docs/GIT_PRACTICE.md)에 따라 직접 수행하고 결과를 캡처합니다.
